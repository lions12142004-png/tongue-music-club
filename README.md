# 舌ゲーム スマホ（HTML）版 v1.3.0（PC版 1119_3 に対応）

PC版（1105_1 から移植し、1119_2 の判定の変更まで反映）を、スマホのブラウザで横向きにして遊べる HTML 版に移植したもの。サーバーは使わず、静的ファイルだけで動く。学習も判定もスマホの中で行い、カメラ映像は保存も送信もしない。

## v1.3.0 で足したもの（ノルマの合算・得点ランキング・曲選択）

- **曲選択**：ホームの「トレーニング開始」→ 曲を選ぶ画面。曲は PC版のメニュー表の最初の3曲と同じ名前（エリーゼのために・仮の曲2・仮の曲3。中身はどれも同じ譜面）。難易度は PC版と同じく NORMAL のみ。
- **みんなのランキング**：曲を選ぶ画面の右上「ランキング」で、EASY・NORMAL・HARD ごとのトップ3（参加者IDと得点）。PC とスマホで同じ曲・同じ難易度なら同じランキング。
- **今日のノルマの合算**：PC とスマホで数えた回数を合計して表示し、合計でクリアを判定する。カレンダーの●△も合計で決まる。
- **記録の送信**：1プレイ・測定・判定テストを受け口（Google スプレッドシート）に送る。通信できないときは端末に残し、あとで送り直す。CSV の書き出しは予備として残した（plays に difficulty・device の列を追加）。
- **設定**：`js/config.js` に受け口の URL と合言葉を書く。空のままなら通信せず、今までどおりこの端末の中だけで数える。受け口の作り方は「1_受け口_AppsScript/受け口の作り方.md」。

## 公開の手順（GitHub Pages）

1. （推奨）`tools/fetch_vendor.ps1`（Mac/Linux は `fetch_vendor.sh`）を実行して、MediaPipe を `vendor/` に入れる。1か月の途中で外部の更新に影響されないようにするため。入れなくても、jsDelivr と Google のサーバーから版を固定して読み込むので動く。
2. このフォルダの中身を GitHub のリポジトリに入れる（`index.html` がいちばん上に来るように）。
3. リポジトリの Settings → Pages で、ブランチ（main）とフォルダ（/root）を選んで保存する。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける。カメラは HTTPS でないと使えないが、GitHub Pages は HTTPS なのでそのままでよい。

ファイルを更新したときは `sw.js` の `VERSION` を上げる（古いキャッシュが消える）。

## 参加者に渡す「ホーム画面に追加する手順」

**iPhone（Safari）**
1. Safari で URL を開く（LINE の中のブラウザではなく Safari で開く）。
2. 下の共有ボタン（□に↑）→「ホーム画面に追加」→「追加」。
3. 以後はホーム画面の「舌ゲーム」アイコンから開く（全画面になり、記録も消えにくくなる）。
4. マナーモードのスイッチが入っていると音が出ない場合があるので、外しておく。
5. 設定 →「画面表示と明るさ」→「自動ロック」を「なし」にしておく（プレイ中に画面が消えないように）。

**Android（Chrome）**
1. Chrome で URL を開く。
2. 右上の︙ →「ホーム画面に追加」（または「アプリをインストール」）。
3. 以後はホーム画面のアイコンから開く。

どちらも、最初に「はじめる」を押したときにカメラの許可を求められるので「許可」を押す。

## PC版から変えたところ

| 項目 | 内容 | 理由 |
| --- | --- | --- |
| SVM の交差検証 | 5分割の各回でも gamma は全データで求めた値を使う | 標準化後なので差は1%未満。カーネル計算を使い回して学習を速くするため |
| 画像の回転 | `cv2.warpAffine` → JS で同じ計算（単精度の座標と双線形補間） | Canvas の rotate より OpenCV に近い値が出るため |
| ロングノーツの加点 | 1フレームごと → 「正解していた時間 ÷ ノーツの長さ × 満点」 | フレームレートが一定でないため |
| ホールド切れ | 不正解60フレーム → 不正解1秒 | 同上 |
| 判定文字の表示時間 | フレーム数 → 秒（30フレーム = 0.5秒） | 同上 |
| タイミング調整 | −10〜10 → −30〜30（1目盛り10ms） | Bluetooth イヤホンなどの遅れに対応 |
| 測定の記録 | Space 長押し → 「記録する」をタップ → 3・2・1 → 自動で記録 | スマホを触った揺れを入れないため |
| 肩が映っていないとき | 置き方ガイドとプレイ中に「肩が映っていません」 | 仕様書の追加 |
| 肩の実行間隔 | 3フレームに1回。判定が15fpsを下回ったら自動で最大5フレームに1回まで広げる | 仕様書どおり |

PC版 1119_2 に合わせて：基準値は測定の1回目だけで決め、2・3回目は学習のみに使う／パワーの足切りはなし（方向は AI とスタビライザだけで決め、パワーは MAX 判定にだけ使う）／ロングノーツの点数とホールド切れは時間で数える（1フレームの経過は250msまで）。演出（Tongue Music Club）はまだ入れていない。

判定モデルは PC版と同じ RF＋SVM のアンサンブル（2:1）。v1.0.0 で測定したデータが端末に残っていれば、開いたときに自動で学習し直す（測り直しは不要）。

判定の数値（口の範囲、基準枠、赤の条件、ノイズ除去、特徴量の計算、パワー、DirStabilizer、得点、ノルマの数え方）は PC版のまま。

## 確認したこと（この環境で）

- **特徴量の一致**：PC版のコード（OpenCV）をそのまま使った参照実装と、合成した顔画像60枚で比べた。21個すべて誤差1%未満（上下左右・前の値は完全一致）。Lab 変換は OpenCV の整数計算を再現し、20万色で a* のずれは13色だけ（1ずれ）。
- **学習**：scikit-learn と同じデータで比べた。RandomForest は予測の一致率 99.5%・確率の差の平均 0.006、SVM（確率づけ込み）は一致率 100%・確率の差の平均 0.002。
- **画面と流れ**：Chrome（にせカメラ）で、タイトル → ID → 置き方ガイド → 測定7ステップ×3回 → 学習 → チュートリアル → 判定テスト → ホーム → プレイ → 一時停止・再開 → リザルト → 設定 → CSV 書き出しまで通した。全部正しく出したときの1プレイはスコア 972,058・MISS 0。
- **学習時間**（RF＋SVM）：約5,800件（拡張後）で4.1秒、チュートリアルで上限まで足した約8,800件で8.4秒（このPC）。スマホでは数倍かかる見込み。1フレームの予測は0.1ms未満。

## 実機で確かめること（報告してほしい値）

開発者画面（タイトルの「舌ゲーム」、またはホーム左上の「PLAYER」を5回タップ）に、fps・処理時間・顔幅・特徴量・確率・肩の値・赤色マスク・最後の測定の混同行列が出る。

1. **判定の fps**：開発者画面の「fps」。15以上が目標。
2. **学習にかかった秒数**：開発者画面の一番下「学習 ○ms（RF / SVM）」。30秒を超える端末では、RF は `js/rf.js` の `nEstimators` を減らし、SVM は `js/svm.js` の交差検証の分割数（`cv`、既定5）を3にすると速くなる。
3. **置き方ガイドの顔幅の目安**：今は `js/app.js` の `FACE_W_MIN = 120`（640px幅の画像での画素数）。開発者画面の「顔幅」を見て、ちょうどよい距離のときの値に合わせる。
4. **左右**：舌を左に出して `left`、左肩を下げて `shoulder_L` になるか。逆になる端末は開発者画面の「左右反転」を ON にすると直る（その端末だけの保険）。

## 記録（CSV）

設定 →「記録を書き出す」で3つの CSV（UTF-8・BOM付き、Excel で文字化けしない）を共有メニューで渡す。共有メニューが使えないブラウザではダウンロードになる。

- `daily_<ID>.csv`：1日1行。`plays` は始めたプレイ数、`completed_plays` は最後（end_time）まで遊んだ数。
- `plays_<ID>.csv`：1プレイ1行。中断したプレイも `completed=0` で残る。`max_count` は MAX パワーで当てた単発ノーツの数。`hold_sec_*` はロングノーツで正解していた秒数。`face_warning_ratio` / `shoulder_missing_ratio` はプレイ中のカメラのフレームのうち顔向き警告・肩なしだった割合。`avg_fps` は判定のフレームレート。
- `calib_<ID>.csv`：測定（`calibration`）と判定テスト（`test`）ごとに1行。
